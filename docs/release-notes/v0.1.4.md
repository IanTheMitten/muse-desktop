# Muse 0.1.4 (alpha)

A fix for Muse not starting on Mac.

## Fixed

- On every Mac, Muse 0.1.2 and 0.1.3 stopped right after opening with
  "Failed to load Python shared library". The signing they added stopped
  Muse's background server from loading its own Python. 0.1.4 signs it so it
  can.

The Mac app ships as a zip (`Muse_aarch64.zip`, `Muse_x64.zip`) as well as a
`.dmg`; on macOS 26 an M-series Mac can refuse to open the `.dmg` itself.

## Install

The builds are not notarized by Apple, so the first launch needs one extra step:

- **macOS:** download the zip, open it (Safari unzips it for you) and drag
  Muse into Applications. Open Muse; when macOS says it could not verify
  Muse, click Done, then go to System Settings → Privacy & Security and click
  Open Anyway. If macOS still says Muse is damaged, run
  `xattr -dr com.apple.quarantine /Applications/Muse.app` in Terminal and
  open it again.
- **Windows:** in the SmartScreen warning choose More info, then Run anyway.

Intel Macs get the app but no smart features.

## Known gaps

- After Reset to file tags, a song added from a plain link (with no record
  found) gets its album name back but stays grouped with the album you moved
  it into.
- Media keys and the Now Playing widget are unverified.
- Some online sources may be unavailable.
